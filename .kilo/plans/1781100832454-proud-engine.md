# План: Handler продления подписки (renew) по public_id

## Постановка задачи

Создать handler для продления (renew) подписки по её `public_id` с возможностью изменить:
- количество трафика (upload/download/total — хранится внутри `metadata.traffic_info`);
- лимит устройств (`max_devices`).

Подписка сохраняет тот же `public_id`, поэтому существующие HAPP-зашифрованные ссылки продолжают работать — клиентские приложения автоматически получат обновлённые метаданные (трафик) при следующем запросе конфига.

## Bounded context

**subscription_issuance** — управление жизненным циклом выданной подписки: создание, получение конфига, продление, отзыв.

## Use case в одном предложении

Администратор продлевает TTL существующей подписки и опционально обновляет `max_devices` и/или `traffic_info` — подписка остаётся доступной по тому же `public_id`.

---

## Варианты реализации

### Вариант 1: минимальный — PATCH-эндпоинт с прямым обновлением полей

Добавить PATCH-эндпоинт, который принимает `additional_hours`, опциональные `max_devices` и `traffic_info`, напрямую обновляет соответствующие поля в БД.

**Плюсы:**
- Минимум кода, быстро.
- Не затрагивает другие слои.

**Минусы:**
- Бизнес-логика (логика продления TTL с учётом expired-статуса, валидация max_devices) остаётся в handler или размазывается.
- `update()` в репозитории всё равно нужно расширять (сейчас обновляет только `status`, `encrypted_link`, `revoked_at`).
- Неудобно тестировать бизнес-правила отдельно от HTTP.

### Вариант 2: полноценный DDD — entity-методы + use case + расширенный repository update

1. **Domain:** Добавить методы на `SubscriptionIssue`:
   - `extend_ttl(additional_hours, now)` — инкапсулирует правило «база для продления = max(now, expires_at)» и автоматически возвращает статус `active`, если подписка была `expired`.
   - `set_max_devices(value)` — с валидацией.
2. **Infrastructure:** Расширить `update()` в `SqlAlchemySubscriptionIssueRepository` — обновлять все поля, а не только `status`/`encrypted_link`.
3. **Application:** `RenewSubscriptionUseCase` — оркестрирует поиск подписки, проверку `is_revoked()`, вызов entity-методов, сохранение.
4. **Presentation:** Тонкий PATCH-эндпоинт.

### Выбор: вариант 2

**Обоснование через DDD/SOLID:**

| Критерий | Оценка |
|----------|--------|
| **Границы домена** | Правило «база продления = max(now, expires_at)» и реактивация expired-подписки принадлежат сущности `SubscriptionIssue`, а не HTTP-слою. |
| **Расширяемость** | В будущем появится `device_access` — метод `set_max_devices` станет точкой вызова domain events. |
| **Тестируемость** | Entity-методы тестируются чистым unit-тестом без БД. Use case тестируется с mock-репозиториями. |
| **SOLID** | Single Responsibility: entity отвечает за свои инварианты, use case — за оркестрацию. Repository порт не меняется — расширяется только имплементация. |
| **Будущий OAuth2 / личный кабинет** | `updated_by` уже передаётся в DTO, готов к переходу с admin-username на client_id. |

**Почему вариант 1 хуже:** размазывает бизнес-правила между handler и прямыми SQL-апдейтами, усложняет тестирование, создаёт долг при добавлении device_access.

## Детальный план реализации

### Шаг 1. Domain: методы на `SubscriptionIssue`

**Файл:** `src/domain/subscription_issuance/entities.py`

```python
def extend_ttl(self, additional_hours: int, now: datetime) -> None:
    """Продлить TTL. База = max(now, текущий expires_at). Если expired — активировать."""
    if additional_hours < 1:
        raise ValueError("additional_hours must be at least 1")
    base = max(now, self.expires_at)
    self.expires_at = base + timedelta(hours=additional_hours)
    if self.status == SubscriptionStatus.expired:
        self.status = SubscriptionStatus.active

def set_max_devices(self, value: int | None) -> None:
    """Установить лимит устройств."""
    if value is not None and value < 1:
        raise ValueError("max_devices must be at least 1 if specified")
    self.max_devices = value

def update_traffic_info(self, traffic_info: TrafficInfo) -> None:
    """Обновить информацию о трафике в metadata."""
    if self.metadata is None:
        self.metadata = SubscriptionMetadata()
    object.__setattr__(self.metadata, "traffic_info", traffic_info)
```

Примечание: `SubscriptionMetadata` — frozen dataclass, поэтому для обновления поля нужно использовать `object.__setattr__`. Альтернативно — заменить `metadata` целиком через `replace()`, но это требует копирования всех полей. `object.__setattr__` — допустимый обходной путь для frozen-объектов, т.к. это внутренний метод сущности.

### Шаг 2. Infrastructure: расширить `update()` в репозитории

**Файл:** `src/infrastructure/db/repositories/subscription_issue.py`

Расширить метод `update()` — синхронизировать все поля сущности с ORM-моделью:

```python
async def update(self, subscription_issue: SubscriptionIssue) -> SubscriptionIssue:
    model = await self._session.get(SubscriptionIssueModel, subscription_issue.id.value)
    if not model:
        raise ValueError(f"SubscriptionIssue with id {subscription_issue.id.value} not found")

    model.status = subscription_issue.status.value
    model.expires_at = subscription_issue.expires_at
    model.max_devices = subscription_issue.max_devices
    model.meta_data = self._map_metadata_to_db(subscription_issue.metadata)
    model.encrypted_link = subscription_issue.encrypted_link
    model.revoked_at = subscription_issue.revoked_at

    await self._session.flush()
    await self._session.refresh(model)
    return self._model_to_entity(model)
```

Это обратно совместимо — существующие вызовы `update()` (в `CreateEncryptedSubscriptionUseCase` и `GetSubscriptionConfigUseCase`) передают полную сущность, просто раньше часть полей игнорировалась.

### Шаг 3. Application: DTO + Use Case

**Файл:** `src/application/subscription_issuance/dto.py`

Добавить:

```python
@dataclass
class RenewSubscriptionDTO:

    max_devices: int | None = None

```

**Файл:** `src/application/subscription_issuance/use_cases.py`

Добавить `RenewSubscriptionUseCase`:

```python
class RenewSubscriptionUseCase:
    def __init__(
        self,
        subscription_repo: SubscriptionIssueRepository,
        time_provider: TimeProvider,
    ):
        self._subscription_repo = subscription_repo
        self._time_provider = time_provider

    async def execute(self, dto: RenewSubscriptionDTO) -> SubscriptionIssueResultDTO:
        subscription = await self._subscription_repo.get_by_public_id(dto.public_id)
        if not subscription:
            raise ValueError(f"Subscription not found: public_id={dto.public_id[:8]}...")

        if subscription.is_revoked():
            raise ValueError(f"Cannot renew revoked subscription: public_id={dto.public_id[:8]}...")

        now = self._time_provider.now()
        subscription.extend_ttl(dto.additional_hours, now)

        if dto.max_devices is not None:
            subscription.set_max_devices(dto.max_devices)

        if dto.traffic_info is not None:
            subscription.update_traffic_info(dto.traffic_info)

        updated = await self._subscription_repo.update(subscription)

        logger.info(
            "Subscription renewed: public_id=%s, additional_hours=%d, new_expires_at=%s",
            dto.public_id[:8] + "...",
            dto.additional_hours,
            updated.expires_at.isoformat(),
        )

        return SubscriptionIssueResultDTO(
            id=updated.id.value,
            public_id=updated.public_id,
            encrypted_link=updated.encrypted_link or "",
            expires_at=updated.expires_at,
            vpn_sources_count=0,
            tags_used=updated.tags_used,
            created_at=updated.created_at,
        )
```

Примечание: `vpn_sources_count` в результате продления не подсчитывается (это не создание, а модификация). Значение 0. В будущем можно убрать это поле из общего DTO или сделать опциональным. Пока ставим 0 как наименее вводящий в заблуждение вариант.

**Файл:** `src/presentation/http/subscription_issuance_router.py`

Добавить эндпоинт:

```python
@router.patch(
    "/subscriptions/{public_id}/renew",
    response_model=EncryptedSubscriptionResponse,
)
async def renew_subscription(
    public_id: str,
    request: RenewSubscriptionRequest,
    admin: str = Depends(get_current_admin),
    subscription_repo: SubscriptionIssueRepository = Depends(get_subscription_repo),
    time_provider: SystemTimeProvider = Depends(get_time_provider),
):
    traffic_info = None
    if request.traffic_info:
        traffic_info = TrafficInfo(
            upload=request.traffic_info.upload,
            download=request.traffic_info.download,
            total=request.traffic_info.total,
        )

    dto = RenewSubscriptionDTO(
        public_id=public_id,
        additional_hours=request.additional_hours,
        updated_by=admin,
        max_devices=request.max_devices,
        traffic_info=traffic_info,
    )

    try:
        result = await RenewSubscriptionUseCase(
            subscription_repo=subscription_repo,
            time_provider=time_provider,
        ).execute(dto)
    except ValueError as e:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail=str(e),
        )

    return EncryptedSubscriptionResponse(
        id=result.id,
        public_id=result.public_id,
        encrypted_link=result.encrypted_link,
        expires_at=result.expires_at,
        vpn_sources_count=result.vpn_sources_count,
        tags_used=result.tags_used,
        created_at=result.created_at,
    )
```

Нужные импорты: `RenewSubscriptionDTO`, `RenewSubscriptionUseCase`, `RenewSubscriptionRequest`, `TrafficInfo`.

## Спецификация API

### `PATCH /api/v1/admin/subscriptions/{public_id}/renew`

**Auth:** HTTP Basic (admin)

**Request:**
```json
{
  "additional_hours": 720,
  "max_devices": 5,
  "traffic_info": {
    "upload": 0,
    "download": 0,
    "total": 107374182400
  }
}
```

| Поле | Тип | Обязательное | Ограничения |
|------|-----|-------------|-------------|
| `additional_hours` | int | да | 1–8760 |
| `max_devices` | int\|null | нет | >= 1 |
| `traffic_info.upload` | int | нет | >= 0 |
| `traffic_info.download` | int | нет | >= 0 |
| `traffic_info.total` | int | нет | >= 0 |

**Response 200:**
```json
{
  "id": "uuid",
  "public_id": "uuid",
  "encrypted_link": "happ://...",
  "expires_at": "2026-07-10T18:00:00Z",
  "vpn_sources_count": 0,
  "tags_used": ["tag1", "tag2"],
  "created_at": "2026-06-10T18:00:00Z"
}
```

**Ошибки:**
- `400` — невалидные данные, подписка отозвана, подписка не найдена (404 — обсуждается ниже)
- `401` — неавторизован
- `422` — ошибка валидации Pydantic

**NB:** Сейчас use case выбрасывает `ValueError("Subscription not found: ...")`, который ловится как 400. В будущем стоит различать доменные ошибки и возвращать 404 для `not_found`. В рамках этого плана оставляем существующий паттерн (400), чтобы не менять контракт в других handler'ах.

## Безопасность и логирование

- `public_id` маскируется: логируются только первые 8 символов (`public_id[:8] + "..."`).
- Значения `traffic_info` (upload/download/total) и `max_devices` **не** логируются.
- `encrypted_link` не логируется.
- Информация о том, кто выполнил продление, сохраняется в логе через поле `updated_by` (в будущем — client_id).
- Все проверки — на серверной стороне, клиенту не доверяется.

---

## Что НЕ входит в этот план

- **Device access enforcement** — сейчас `max_devices` просто хранится, но не проверяется при получении конфига. Это отдельная задача.
- **Аудит** — таблица `audit_events` ещё не создана. Логирование через стандартный `logging` достаточно на текущем этапе.
- **Перешифрование HAPP-ссылки** — не требуется, т.к. `public_id` не меняется, конфиг генерируется динамически.

## Альтернативы (отклонённые)

**Пересоздание подписки с новым public_id при продлении:**
- Дало бы чистый аудит (каждый период — отдельная запись).
- Но сломало бы существующие HAPP-ссылки у клиентов.
- Усложнило бы логику: нужно копировать VPN-источники, metadata, behavior.
- Выбрано «продление на месте» как более практичное для пользователей.
